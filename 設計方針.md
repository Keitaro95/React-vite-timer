GitHub Actions + GCP を使った CI/CD 自動化ドキュメント

---

## 1. GitHub リポジトリ側の設定

### 1.1 ブランチ保護ルール

* **development**
  通常は制限なし（開発用ブランチなので誰でも push/PR OK）
* **stage**
  「Require pull request reviews before merging」を設定し、最低1名のレビュワー承認を必須
* **main**
  「Require status checks to pass」「Require pull request reviews」「Include administrators」などを ON にし、直接 push は不可

### 1.2 Environments（環境）設定

リポジトリの **Settings > Environments** で以下を作成し、それぞれにシークレットや承認フローを設定します。

| Environment 名   | 用途                     | Protection／Secrets                        |
| --------------- | ---------------------- | ----------------------------------------- |
| **development** | ローカル動作確認（unit＋ローカル）    | （特に作らずにローカル CI のみ動くようにする）                 |
| **stage**       | Integration テスト＆GCP上検証 | `WIF_PROVIDER`、`WIF_SA_STAGE`（デプロイ用 SA）   |
| **production**  | 本番デプロイ                 | `WIF_PROVIDER`、`WIF_SA_PROD`（本番用 SA）、承認必須 |

※ Production には Approval gates（マニュアル承認）や Deployment branches の制限も設定可能です。

---

## 2. GCP 側の設定

1. **Workload Identity Federation 設定**

   * GCP コンソール > IAM & 管理 > Workload Identity Federation で GitHub Actions 用プロバイダーを作成
   * リポジトリ or org を指定し、`sts.googleapis.com` のトークン発行を許可
   * プロバイダーの完全名を `WIF_PROVIDER` として GitHub シークレットに登録

2. **サービスアカウント作成・権限付与**

   * **stage 用**: `sa-stage@PROJECT_ID.iam.gserviceaccount.com`

     ```bash
     gcloud iam service-accounts create sa-stage \
       --display-name="GitHub Actions (Stage)"
     gcloud projects add-iam-policy-binding PROJECT_ID \
       --member="serviceAccount:sa-stage@PROJECT_ID.iam.gserviceaccount.com" \
       --role="roles/artifactregistry.writer"
     gcloud projects add-iam-policy-binding PROJECT_ID \
       --member="serviceAccount:sa-stage@PROJECT_ID.iam.gserviceaccount.com" \
       --role="roles/run.admin"
     ```
   * **production 用**: `sa-prod@PROJECT_ID.iam.gserviceaccount.com`
     同様に `artifactregistry.writer`、`run.admin`、`iam.serviceAccountUser` 等を付与

3. **Cloud Run サービス準備**

   * `my-service-stage`（ステージ環境用）、`my-service-prod`（本番用）
     ※ 環境ごとに別サービスとすることでリソースを分離・管理しやすくなります。

---

## 3. GitHub Actions ワークフロー例

`.github/workflows/ci-cd.yml`

```yaml
name: CI / CD Pipeline

on:
  push:
    branches:
      - development
      - stage
      - main
  workflow_dispatch:

jobs:
  # development ブランチ向け
  dev:
    if: github.ref == 'refs/heads/development'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install dependencies
        run: npm ci
      - name: Run unit tests
        run: npm test
      - name: Local deploy (Docker run)
        run: |
          docker build -t local-dev:${GITHUB_SHA} .
          docker run -d --name local-dev -p 8080:8080 local-dev:${GITHUB_SHA}

  # stage ブランチ向け
  stage:
    if: github.ref == 'refs/heads/stage'
    runs-on: ubuntu-latest
    environment: stage
    needs: dev
    steps:
      - uses: actions/checkout@v3
      - name: Install dependencies
        run: npm ci
      - name: Run integration tests
        run: npm run test:integration
      - name: GCP Auth
        uses: google-github-actions/auth@v0
        with:
          token_format: 'access_token'
          workload_identity_provider: ${{ secrets.WIF_PROVIDER }}
          service_account: ${{ secrets.WIF_SA_STAGE }}
      - name: Docker login
        uses: docker/login-action@v1
        with:
          registry: '${{ vars.REGION }}-docker.pkg.dev'
          username: 'oauth2accesstoken'
          password: ${{ steps.auth.outputs.access_token }}
      - name: Build & push
        uses: docker/build-push-action@v3
        with:
          context: .
          push: true
          tags: ${{ vars.REGION }}-docker.pkg.dev/${{ vars.GCP_PROJECT_ID }}/${{ vars.ARTIFACT_REPO }}/my-service-stage:${{ github.sha }}
      - name: Deploy to Cloud Run (stage)
        uses: google-github-actions/deploy-cloudrun@v0
        with:
          service: my-service-stage
          region: ${{ vars.REGION }}
          image: ${{ vars.REGION }}-docker.pkg.dev/${{ vars.GCP_PROJECT_ID }}/${{ vars.ARTIFACT_REPO }}/my-service-stage:${{ github.sha }}

  # main ブランチ向け
  prod:
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    needs: stage
    steps:
      - uses: actions/checkout@v3
      - name: Install dependencies
        run: npm ci
      - name: Run smoke tests
        run: npm run test:smoke
      - name: GCP Auth
        uses: google-github-actions/auth@v0
        with:
          token_format: 'access_token'
          workload_identity_provider: ${{ secrets.WIF_PROVIDER }}
          service_account: ${{ secrets.WIF_SA_PROD }}
      - name: Docker login
        uses: docker/login-action@v1
        with:
          registry: '${{ vars.REGION }}-docker.pkg.dev'
          username: 'oauth2accesstoken'
          password: ${{ steps.auth.outputs.access_token }}
      - name: Build & push
        uses: docker/build-push-action@v3
        with:
          context: .
          push: true
          tags: ${{ vars.REGION }}-docker.pkg.dev/${{ vars.GCP_PROJECT_ID }}/${{ vars.ARTIFACT_REPO }}/my-service-prod:${{ github.sha }}
      - name: Deploy to Cloud Run (prod)
        uses: google-github-actions/deploy-cloudrun@v0
        with:
          service: my-service-prod
          region: ${{ vars.REGION }}
          image: ${{ vars.REGION }}-docker.pkg.dev/${{ vars.GCP_PROJECT_ID }}/${{ vars.ARTIFACT_REPO }}/my-service-prod:${{ github.sha }}
```

### ポイント解説

1. `if: github.ref == 'refs/heads/...`
   ブランチごとに Job を切り分け、不要なステップをスキップ
2. `environment: stage` / `production`
   GitHub Environments の保護設定（シークレットや承認ゲート）を適用
3. `needs:`
   前段の Job 成功を待ってから実行（例：stage→main）
4. サービス名を分ける
   Cloud Run 上は `my-service-stage` / `my-service-prod` と別名にして、環境を並列運用
5. テストフェーズ

   * development: `npm test`（unit）＋Docker run local
   * stage: `npm run test:integration`
   * main: `npm run test:smoke`

---

## 4. ローカルからの npm コマンド起動

`package.json` の `scripts` に以下を追加すると手軽に呼び出せます。

```json
{
  "scripts": {
    "deploy:dev":   "gh workflow run ci-cd.yml --ref development",
    "deploy:stage": "gh workflow run ci-cd.yml --ref stage",
    "deploy:prod":  "gh workflow run ci-cd.yml --ref main"
  }
}
```

* `GH_TOKEN`（`repo, workflow` scope）を環境変数にセットしておくこと。

---

以上の手順で、

1. **development** → unit-test＋ローカル起動
2. **stage**       → integration-test＋GCPステージ環境デプロイ
3. **main**        → smoke-test＋GCP本番デプロイ

が自動化できます。

## 🔧 Dockerfile（Multi-stage）

### ✅ 共通の前提

* `npm run dev`：開発用（ホットリロード付き）
* `npm run build`：本番ビルド（`dist/` 生成）
* `npm run preview`／`serve -s dist`：GCP 上での静的ホスティング

---

### 1. 開発用 Dockerfile

```dockerfile
# 開発ステージ
FROM node:18-alpine
WORKDIR /app

# package.json だけ先にコピーしてキャッシュ
COPY package*.json ./
RUN npm install

COPY . .

# Vite dev サーバー用に公開
EXPOSE 3000

CMD ["npm", "run", "dev"]
```

* `vite.config.ts` で server.host を `0.0.0.0` に設定しておく（コンテナ外からアクセス可）
* Docker Compose を使って、コードの更新をリアルタイム反映

---

### 2. 本番／ステージ用 Dockerfile

```dockerfile
# ビルドフェーズ
FROM node:18-alpine AS build
WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .
RUN npm run build

# 本番ステージ（Nginx or busybox httpd）
FROM nginx:stable-alpine AS production
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf   # optional
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

* Multi-stage によって余分な依存を含まない軽量イメージに

## ⛓ Docker Compose 例

① **docker-compose.dev.yml**（開発用）：

```yaml
version: '3.9'
services:
  frontend:
    build:
      context: .
      dockerfile: Dockerfile.dev
    volumes:
      - .:/app
      - /app/node_modules
    ports:
      - 3000:3000
    environment:
      - NODE_ENV=development
```

② **docker-compose.yml**（ステージ／本番用）：

```yaml
version: '3.9'
services:
  frontend:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - 80:80
```

* `Dockerfile.dev` は開発用、`Dockerfile` は本番ビルド用として使い分けるスタイルも一般的

## 🚀 GitHub Actions + GCP 連携

前回答で整理した CI/CD ワークフローに組み込みたい場合：

* **stage/main** ブランチ用 job では、Dockerfile を使ってビルドし、GCP にデプロイ
* 使用 Action：`docker/build-push-action@v3` ＋ `google-github-actions/deploy-cloudrun@v0`

```yaml
# stage/job 抜粋
- uses: docker/build-push-action@v3
  with:
    context: .
    push: true
    tags: ${{ vars.REGION }}-docker.pkg.dev/.../my-frontend-stage:${{ github.sha }}

- uses: google-github-actions/deploy-cloudrun@v0
  with:
    service: my-frontend-stage
    image: ${{ vars.REGION }}-docker.pkg.dev/.../my-frontend-stage:${{ github.sha }}
```

本番（main） は `my-frontend-prod` サービス、サービスアカウントも別に設定してください。
